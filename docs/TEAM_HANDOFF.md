# 팀 실행 안내 — 2026-10-22

## 1. 연결 구조

브라우저와 확장은 `http://127.0.0.1:5173/api/score`를 호출합니다. 웹 개발 서버가 `/api/score`를 `/api`로 바꿔 백엔드 `http://127.0.0.1:8001`에 전달하며 실시간 STT WebSocket도 중계합니다. 웹 서버와 백엔드를 모두 켜야 합니다. 5173이 사용 중이면 자동으로 다른 포트로 옮기지 않도록 `--strictPort`를 사용합니다.

GPU 서버를 사용하는 팀원은 서버에서 백엔드를 실행하고 본인에게 이미 허용된 SSH 접속으로 로컬 8001 포트를 전달합니다. SSH 주소·계정·개인키는 이 저장소에서 배포하지 않습니다. 다른 기기에서 사용할 공인 서비스 주소나 배포 설정은 아직 제공하지 않습니다.

## 2. API 설정과 데이터

루트 `.env.example`을 `.env`로 복사하고 기존 팀 키를 별도로 설정합니다.

| 설정 | 사용처 |
|---|---|
| `AX_API_KEY` | A.X STT, A.X-K2 대화 역할 |
| `SOLAR_API_KEY` | Solar Pro 2 설명·의미 비교 |
| `VARCO_API_KEY` | 두리 음성 TTS |
| `EXAONE_API_KEY`, `EXAONE_ENDPOINT_ID` | EXAONE을 사용하는 분석·검증 모듈 |
| `MIDM_API_KEY`, `MIDM_MODEL_ID` | 믿:음 역할을 사용하는 분석 모듈 |
| `MEMFLIX_DATA_DIR` | 새 계정·기록의 비공개 저장 폴더. 기본 `data/memflix/private` |
| `SCORING_MODEL_PATH`, `CONTENT_SCORING_MODEL_PATH` | 별도로 승인된 참조분포 파일 경로 |

현재 코드의 모델 ID는 A.X-K2와 `solar-pro2`입니다. 브라우저용 `VITE_*` 환경변수에 API 키를 넣지 마세요. `apps/extension/extension/connection.json`의 `key`는 Chrome 개발 확장 ID를 고정하는 **공개키**이며 API 키·개인키가 아닙니다. 백엔드가 같은 정확한 extension origin을 사용하므로 변경하지 않습니다.

참조분포를 받지 않은 상태에서도 계정·음성 저장을 점검할 수 있습니다. 이때 점수 없음은 정상적인 측정 불가 상태입니다. 연구 자료를 받지 않은 팀원은 과거 분류 실험까지 재현할 수는 없습니다.

## 3. 계정과 가족 연결

1. 웹에서 **일반 사용자** 계정을 새로 만듭니다. 기존 운영 계정과 기록은 복제되지 않습니다.
2. 사용자 화면의 **가족 연결**에서 공유 코드를 받습니다.
3. 별도의 패밀리 계정에서 연결 대상의 아이디·이름과 공유 코드를 입력합니다.
4. 확장에는 일반 사용자 계정으로 로그인합니다. 패밀리 계정은 웹에서 리포트를 봅니다.
5. 대화를 저장한 뒤 패밀리 화면에서 해당 기록과 녹음을 확인합니다. 점수·설명 기능의 알려진 제한은 README를 참고합니다.

## 4. 시연 점검

김장 뉴스 `q-2EmyuAOmM`을 사용합니다. 설정에서 자동 음성·자동 마이크·무음 종료 5초를 선택한 다음 사용자 동작으로 인사를 시작합니다. 두리 음성이 끝나면 짧게 말하고 6~7초 조용히 기다립니다.

- 목소리 재생 → 마이크 시작 → 자동 종료 → 전사 표시를 각각 확인합니다.
- 영상 대화에서 정지 → 답변 → 영상 재개를 확인합니다. 짧은 뉴스는 시청 중 한 번과 시청 후 한 번을 계획합니다.
- 대화 대기 중 접기·재열기를 두 번 반복하고 창 너비·버튼을 확인합니다.
- 영상 끝까지 본 뒤 마지막 대화에 답하고, 다음 만남을 선택해 이야기 저장을 누릅니다.
- 패밀리 화면에서 기록과 녹음을 확인합니다. 다음 로그인에서 지난 대화·약속이 인사에 반영되는지도 별도로 확인합니다.

영상 재생 실패나 Chrome 음성 권한 문제를 회상 성능 실패로 세지 않습니다. 자동 검사 성공과 물리 마이크 성공도 별도로 기록합니다.

### localhost에서 소리·전사 확인 (2026-10-31)

`localhost`에서 로그인되는데 소리와 전사가 실패하는 경우, 로그인 성공만으로 외부 음성 API 연결까지 확인된 것은 아닙니다.

1. 백엔드를 실행하는 **저장소 루트** `.env`에 `VARCO_API_KEY`(TTS), `AX_API_KEY`(ASR)가 있는지 확인하고 백엔드를 재시작합니다. 키는 GitHub나 채팅에 올리지 않습니다.
2. 같은 브라우저에서 `http://localhost:5173/api/score/health`를 엽니다. `tts`/`stt`는 키가 설정되었는지만 나타내며, `true`여도 만료·호출 제한·네트워크 문제는 따로 확인해야 합니다. `false`면 해당 키의 로딩부터 확인합니다.
3. 인사 화면에서 **소리로 듣기 → 말하기 → 짧게 답하기 → 말 다 했어요** 순서로 확인합니다. 현재 master 웹은 녹음 종료 후 전사하며, 성공하면 **말씀하신 내용**이 표시됩니다. 전사 처리는 녹음 길이에 따라 기다려야 할 수 있습니다.
4. 실패 시 화면에 표시된 HTTP 상태와 개발자 도구 Network의 `/api/score/tts` 또는 `/api/score/transcribe` 상태를 전달합니다. 계정 쿠키·API 키·음성 본문은 공유하지 않습니다.

두 키가 설정되어 있어도 팀원 컴퓨터의 실제 API 응답을 확인하기 전에는 원인을 확정하지 않습니다. 허용 목록의 `192.168.0.178:5173` 추가는 로그인용이며 다른 기기의 HTTP 마이크 제한을 해제하지 않습니다.

### 반응형 후속 변경: 확장 0.3.9 (2026-10-22)

두리 대화창은 부모 브라우저 너비를 기준으로 확대합니다. 1280px에서 창 전체 너비 392px·본문 16px, 1920px에서 520px·19.2px, 2560px에서 560px·20px입니다. 작은 화면에서는 가로 폭을 화면 안에 맞추고 내용 영역을 스크롤합니다. 말하기 버튼은 스크롤 영역 밖에 유지합니다. 캐릭터와 끌기 영역은 기존 크기를 유지합니다.

GPU 서버에서 `npm test` 127개, `npm run build:ext`, `npm run test:frame` 6개를 통과했습니다. 실제 빌드를 가상 입력으로 띄워 320~2560px 너비, 500px 높이의 짧은 화면, 접기·재열기 3개 크기에서 너비 복원을 확인했습니다. 실제 Chrome 확장 설치 환경의 권한·마이크·음성 응답을 검증한 것은 아닙니다.

가상 화면 재현: 확장 빌드 후 `node verify/make-responsive-review.mjs`를 실행하고 `dist-responsive-review/`를 로컬 정적 서버로 엽니다. 이 페이지는 실제 계정·API·마이크에 연결하지 않습니다. 배포 폴더에는 `dist-ext/`만 사용합니다.
