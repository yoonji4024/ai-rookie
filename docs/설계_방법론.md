# 음성 분석 설계 방법론

> 어떤 기준으로 피처를 만들었고, 왜 그렇게 설계했고, 모델을 어디에 왜 썼는가
> 분석 에이전트(음성·스코어링) · 박윤지 · 2026-07-21

---

## 0. 설계를 관통하는 원칙 4가지

이 프로젝트에서 반복적으로 적용한 판단 기준입니다. 개별 결정의 이유는 대부분 여기서 나옵니다.

1. **신호의 방향은 문헌이 아니라 데이터가 정한다.**
   직관과 반대인 축이 실제로 있었습니다(휴지). 가정으로 정하면 라벨과 거꾸로 갑니다.
2. **길이 편향을 항상 의심한다.**
   말을 많이 하면 무엇이든 많이 나옵니다. 총량이 아니라 **비율**로 정규화합니다.
3. **점수는 규칙이 매기고, LLM은 해석만 한다.**
   LLM이 채점하면 재현이 안 되고 방어할 수 없습니다.
4. **채택은 측정된 개선으로만 정당화한다.**
   "최신 모델을 썼다"는 근거가 아닙니다. 개선이 없으면 버립니다.

## 1. 음향 피처 — 무엇을 왜 쟀나

### 1.1 왜 원본 오디오에서 직접 뽑는가

런타임에서는 A.X STT가 음성을 텍스트로 바꿉니다. 그런데 STT는 발화를 **매끄럽게 다듬습니다.**
"제가 즈, 나, 제, 제가" → "제가" 처럼요. 이 더듬거림이 바로 인지 저하의 단서인데,
텍스트만 쓰면 신호가 사라진 뒤의 결과를 보게 됩니다.

그래서 음향 피처는 **STT를 거치지 않고 원본 파형에서 직접** 뽑도록 설계했습니다.
(→ 이 판단이 옳았음은 §5의 STT 실측으로 입증됐습니다)

### 1.2 피처 그룹과 선정 근거

최종 51개. 그룹별로 "무엇을 재는가"와 "왜 넣었는가"입니다.

| 그룹 | 개수 | 재는 것 | 선정 근거 | 그룹 AUC |
|---|---|---|---|---|
| **pause** | 6 | 말하다 멈추는 빈도·길이·비율 | word-finding 곤란이 휴지로 나타난다는 임상 관찰 | 0.783 |
| **tempo** | 3 | 발성 구간의 분절 패턴 | 발화가 잘게 끊기는지 길게 이어지는지 | 0.744 |
| **voice(음질)** | 12 | F0, jitter 3종, shimmer 3종, HNR, CPP | 신경퇴행이 발성 안정성을 떨어뜨림. MDVP 표준 패널 | 0.728 |
| **MFCC** | 26 | 소리의 스펙트럼 지문 | 음성 인식의 표준 특징, 음색 변화 포착 | 0.761 |
| **spectral** | 2 | ZCR(소리 거칠기) | MFCC와 중복 적은 것만 남김 | 0.556 |
| **duration** | 2 | 총 발화·발성 시간 | 판별력은 세지만 **편향 의심** → §3.2 | 0.815 |

**음질 패널을 표준 그대로 넣은 이유**: jitter는 음높이의 미세 떨림, shimmer는 크기의 미세
떨림, HNR은 배음 대비 잡음, CPP는 주기성·명료도입니다. 성대 진동의 불규칙성을 여러 각도로
재는 것이라, 하나만 쓰기보다 패널로 넣고 **어느 것이 신호인지 데이터로 고르는** 방식을 택했습니다.

### 1.3 넣었다가 뺀 것 — 판단 기준

**포먼트(F1~F3, 6개) — 제거**
성도 형태를 재는 지표로 조음 정확도와 관련이 있어 넣었지만, Kang에서 판별력이 없었습니다
(f1_mean 0.503으로 사실상 무작위, 최고가 f3_std 0.651). 음질 그룹에 넣어도 AUC가
0.727 → 0.724로 제자리였습니다. **제거하니 음향 전체가 0.854 → 0.871로 올랐습니다.**
표본이 77명뿐이라 약한 피처는 과적합만 늘립니다.

**spectral 4종(centroid/bandwidth/rolloff/rms) — 제거**
그룹 AUC 0.543. rms는 0.51로 완전히 죽었고, 나머지도 MFCC와 중복됩니다. ZCR(0.709)만 남겼습니다.

> **판단 기준**: 피처를 늘리는 게 아니라 **줄여서 성능이 오르면 줄인다.**
> n=77에서는 약한 피처가 신호가 아니라 잡음입니다.

### 1.4 계산 비용도 설계 변수였다

CPP는 켑스트로그램을 2ms 간격으로 계산해서, 화자당 900초 오디오에 적용하면 **파일당 10분**이
걸렸습니다. 77명이면 실험을 한 번 돌리는 데 12분입니다. 반복 실험이 불가능해집니다.

→ CPP 입력을 **중간 60초로 제한하고 간격을 10ms로** 늘렸습니다. 평균 CPP는 60초 샘플로도
안정적이라 신호는 유지되고(voice 그룹 0.728 유지), 속도만 확보했습니다.

## 2. 한국어 비유창성 — LLM에서 규칙으로

### 2.1 왜 필요했나

발화 5축 중 **버벅임이 AUC 0.684로 가장 약했습니다.** 구성이 간투사 비율(음·어 정규식),
단어 반복, 휴지 빈도 셋뿐이라 한국어 비유창성의 표면만 긁고 있었습니다.

실제 Kang MCI 발화를 보면 훨씬 풍부합니다:
> "아니, 이제 우리, **저기 뭐야** 거기 내, **저기 뭐야** 으, 제가 **즈, 나, 제, 제가** 저기, 거기서 일하는 거 있어요."

단어 찾기 실패("저기 뭐야"), 단음절 파편 반복("즈, 나, 제, 제가"), 지시어 남용("저기")이
한 문장에 다 들어 있습니다.

### 2.2 먼저 LLM(믿:음)으로 시도 → 실패

한국어 특화 모델에 마커 탐지를 맡겼습니다. 결과:

- **짧은 예문(37자)에서는 정확합니다.** 조사 오류·자기 수정·지시어 남용·단어 찾기를
  근거까지 정확히 집어냅니다.
- **실제 대화체 전사에서는 실패합니다.** MCI 발화의 명백한 비유창성을 못 찾고, 반대로
  HC 발화에서 없는 마커를 만들어냈습니다(긴 문장을 통째로 "조사 오류"라고 인용).

청크를 3000자 → 329자로 줄이고 프롬프트를 조여도 해결되지 않았습니다. 결과 AUC 0.50~0.55로
신호가 아니라 잡음이었습니다.

> **디버깅에서 배운 것**: 처음엔 "호출 실패"로 보였습니다. 예외를 잡아 빈 결과로 되돌리는
> 코드 때문에 **'실패'와 '마커 없음'이 구분되지 않았고**, 검증기가 데이터 없이
> "채택 보류" 판정을 내릴 뻔했습니다. 원시 응답을 직접 본 뒤에야 모델은 멀쩡하고
> 과제 주는 방식이 틀렸다는 걸 알았습니다.

### 2.3 규칙 기반으로 전환 → 성공

관찰된 패턴이 규칙적이어서 정규식으로 직접 잡았습니다. API 호출 없이 완전 재현됩니다.

| 마커 | HC | MCI | AUC |
|---|---|---|---|
| 어미 미완성 | 0.0244 | 0.0424 | **0.736** |
| 단음절 파편 반복 | 0.0005 | 0.0094 | **0.726** (MCI 19배) |
| 지시어 남용 | 0.0144 | 0.0215 | **0.692** |

**버벅임 축 0.690 → 0.879**, 전체 분류기 **0.833 → 0.897**.

> **여기서도 "줄이면 오른다"가 반복됐습니다.** 마커 7개 전부 쓴 것(0.894)보다
> 검증 통과한 3개만 쓴 게 더 좋았습니다(0.897).

### 2.4 LLM을 버린 게 아니다

믿:음이 짧은 예문에서 보여준 **마커 정의**(조사 오류·자기 수정·지시어 남용·단어 찾기)가
그대로 규칙의 뼈대가 됐습니다. **LLM으로 탐색하고, 검증한 뒤 재현 가능한 규칙으로 구현**한
셈입니다. 이 순서는 다른 피처 설계에도 쓸 수 있습니다.

## 3. 스코어링 루브릭 — 어떻게 점수로 바꾸나

### 3.1 방향을 데이터가 정하게 한 이유

직관적으로는 "휴지가 많으면 나쁨"입니다. 그런데 Kang에서는 **HC가 오히려 더 자주 쉽니다**
(pause_ratio 0.093 vs MCI 0.035). MCI는 짧게 끊어 답하고 덜 쉬는 패턴이었습니다.

직관대로 루브릭을 짰다면 점수가 라벨과 **거꾸로** 갔을 겁니다.

→ 각 피처의 부호를 **학습 fold의 HC/MCI 평균차로 결정**하도록 했습니다.
검증 시에는 fold 안에서만 fit해서 leakage를 막습니다.

### 3.2 편향 피처를 점수에서 제외한 이유

가장 강한 피처가 "총 발화 시간"(AUC 0.866)이었습니다. HC 708초 vs MCI 449초.
그런데 이건 인지력이 아니라 **그날 인터뷰가 짧았을 수도** 있습니다.

검증: 이 계열 2개를 빼고 다시 측정 → **음향만으로 AUC 0.813 유지**.
발화량과 독립적으로 음향 신호가 실재함을 확인했습니다.

→ 점수 산출에서는 발화량 계열을 **제외**하고, 보고 시에는 (a) 전체 0.871,
(b) 발화량 제거 0.813 **두 값을 함께** 표기합니다.

**같은 함정이 한국어 마커에서 재발했습니다.** 발화당 정규화 시 간투사가 AUC 0.785로
최강 신호처럼 보였는데, 형태소당으로 바꾸니 **0.578로 무너졌습니다.**
HC 발화가 평균 27.5형태소, MCI가 15.8형태소로 2배 차이라, 발화당으로 세면 길게 말하는
쪽이 무엇이든 많이 나옵니다. → **모든 언어 피처를 형태소당으로 통일**했습니다.

### 3.3 점수 환산식의 근거

```
점수 = 100 × Φ(z + 1)     z = (측정값 − HC평균) / HC표준편차 × 방향
```

- **HC 분포를 기준(규준)으로** 삼습니다. 신경심리 검사가 정상군 규준 대비 편차로
  판정하는 관행과 같습니다.
- `+1` 이동의 의미: **HC 평균이 84점**, HC 대비 **−1SD가 50점**이 됩니다.
  신경심리에서 −1SD를 경계로 보는 관행과 맞춥니다.

### 3.4 등급 컷을 정한 과정

단조성(등급이 나빠질수록 MCI 비율 증가)과 최소 인원을 만족하는 컷을 탐색했습니다.

| 컷 | 정상 | 관찰 필요 | 주의 관찰 | MCI 비율 |
|---|---|---|---|---|
| 70/45 | 41명 | 24명 | 12명 | 22% → 79% → 100% |
| **85/50 (채택)** | 16명 | 43명 | 18명 | **6% → 49% → 100%** |

**85/50을 택한 이유**: 선별도구에서는 **MCI를 놓치는 쪽이 더 큰 비용**입니다.
정상 등급의 MCI가 22%에서 6%로 줄어듭니다.

**대가와 대응**: 이 컷에서는 건강한 분 37명 중 22명(59%)이 중간 등급에 들어옵니다.
그래서 중간 등급 이름을 "위험"이 아니라 **"관찰 필요"**로 바꿨습니다.
건강한 분 다수가 받는 등급에 위협적인 이름을 쓰면 불필요한 불안을 유발하고,
반복되면 도구 신뢰가 무너집니다. **등급 이름은 임상적 의미가 아니라 사용자가 받게 될
메시지로 정했습니다.**

## 4. 모델을 어디에 왜 썼나

### 4.1 역할 분담

| 모델 | 역할 | 선정 이유 |
|---|---|---|
| **SKT A.X K1** | 시청 중 질문 생성(draft) | 실시간 대화 생성. 자막 근거로 질문 후보 3개 |
| **A.X STT** | 런타임 음성→텍스트 | Batch는 **화자 분리 지원** — 인터뷰에서 참가자만 추출 가능 |
| **LG EXAONE** | 질문 타이밍 판정(judge) + **교차검증** | 생성과 판정을 분리하기 위해 다른 모델 사용 |
| **Upstage Solar** | 요약·장면 매칭·보호자 리포트 | 구조화 JSON 출력과 한국어 서술 |
| **KT 믿:음** | 탐지 근거 설명 | 분류 결과를 한국어로 풀어 설명 |
| **NC VARCO** | 데모 음성 합성 | 노년 화자 65명 보유, seed 고정으로 재현 가능 |

### 4.2 "점수는 규칙, 해석은 LLM" 원칙

스코어링에서 LLM에게 채점을 맡기지 않았습니다. 이유는 세 가지입니다.

1. **재현성** — 같은 입력에 같은 점수가 나와야 합니다.
2. **방어 가능성** — "왜 63점인가"에 계산식으로 답할 수 있어야 합니다.
3. **검증 가능성** — 점수가 라벨과 맞는지 AUC로 잴 수 있어야 합니다.

LLM은 **이미 나온 점수를 사람이 이해할 말로 옮기는** 역할만 합니다.
믿:음에는 피처명 44개의 우리말 사전을 함께 넘깁니다
(`lg_krr_fragment_repeat_rate` → "'제가, 즈, 나, 제'처럼 짧은 조각을 되풀이하는 빈도").

### 4.3 생성 모델과 검증 모델을 분리한 이유

Solar가 쓴 리포트를 Solar가 검증하면 **같은 편향을 공유**합니다.
그래서 검증은 EXAONE이 독립적으로 합니다 — 리포트가 측정값을 왜곡하지 않았는지,
진단처럼 읽히지 않는지, 장면 매칭이 타당한지.

### 4.4 타이밍 게이트의 3단계 구조

시청을 방해하지 않는 게 목적이라, 질문을 **많이** 하는 게 아니라 **제때** 하는 게 성능입니다.

```
hard block (규칙)  →  draft (A.X K1)  →  judge (EXAONE)  →  refine
```

**hard block을 LLM 앞에 둔 이유**: A.X는 팀당 **RPS 3**이 한도입니다(팀원과 공유).
규칙으로 먼저 걸러야 API를 아끼고, 응답 지연도 줄어듭니다.
차단 조건은 질문 간격 90초 미만, 장면 경계 ±3초(몰입 구간), 세션당 5회 초과, 사용자 발화 중입니다.

실측: 뉴스 1266초에서 **84개 평가 시점 중 5회만 질문하고 80회는 침묵**했습니다.

## 5. 검증 체계 — 무엇을 어떻게 확인했나

### 5.1 분류 성능

- **subject-level 5-fold CV**: Kang은 파일 1개가 화자 1명이라 행 단위 분할이 곧 화자 단위
  분할입니다. 같은 사람이 학습·시험에 겹치면 목소리를 외워서 맞히는 반칙이 됩니다.
- 지표: ROC-AUC(OOF), Recall@90%Spec, 피처별 단변량 AUC, 그룹별 ablation.

### 5.2 LLM 출력 검증 (4종)

| 항목 | 방법 |
|---|---|
| 스키마 준수 | 필수 키·축 이름 일치 |
| **근거성** | 출력에 등장하는 **숫자가 입력에 실제로 있는지** 자동 대조 |
| 진단 단정 | 금지어("치매", "경도인지장애", "환자", "진단됩니다") 검사 |
| 재현성 | 같은 입력 반복 호출 시 점수 인용·스키마 일관성 |

실패 시 **무엇이 틀렸는지 피드백해 재생성**하는 루프를 넣었습니다.
1차 검증에서 3회 중 1회 없는 수치를 인용했으나, 온도를 0으로 낮추고 숫자 인용 규칙을
강화한 뒤 **3/3 통과, 전부 1회 시도**로 개선됐습니다.

### 5.3 등급 타당성

등급이 나빠질수록 MCI 비율이 **단조 증가**하는지 확인합니다.
최종: 정상 22% → 관찰 필요 79% → 주의 관찰 **100%**(HC 0명).

### 5.4 한계를 측정한 두 실험

**STT 도메인 시프트** — 지금 성능이 실전에서 재현되는가
Kang 40명을 STT로 전사해 gold와 비교. 지시어·간투사는 100% 이상 보존되나,
**어미 미완성은 43.6%만 남고 판별력이 0.760 → 0.527로 붕괴**했습니다.
WER 0.352.

**TTS 한계** — 합성 음성으로 검증 가능한 범위
MCI 대본으로 만든 TTS가 발음 정확도 **100점**(실제 건강한 사람 90점보다 높음).
성대가 없어 jitter·shimmer가 생기지 않기 때문입니다.

> 두 실험은 성능을 높이지 않습니다. **무엇을 주장할 수 없는지**를 확정합니다.
> 이 경계가 없으면 gold 기준 성능을 실전 성능으로 오해하게 됩니다.
