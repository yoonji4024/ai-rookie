# 근거 기반 해석과 검증

## 문제

점수는 규칙으로 내고 해석만 Solar에 맡기는 구조였음. 그런데 Solar에 준 것이 점수와 측정값뿐

* "침묵 시간 62점"이 왜 의미 있는지에 대한 근거가 입력에 없음
* → 해석이 모델의 상식에서 나옴. 무엇에 근거했는지 추적 불가

## 구조

점수 → 근거 검색 → 해석 → 검증 → 리포트

각 단계의 주체를 분리

| 단계 | 주체 | 하는 일 |
|---|---|---|
| 채점 | 규칙 | 점수를 정한다 |
| 검색 | RAG | 그 축의 근거를 가져온다 |
| 해석 | Solar | 루브릭과 근거로 풀어쓴다 |
| 검증 | 규칙 + EXAONE | 해석을 판정한다 |

서로의 영역을 침범 못 하게 입력 자체를 제한

## 근거 코퍼스

`src/rag/corpus.py`, 16건. 자유 검색을 허용하지 않고 이 안에서만 고름

| 종류 | 건수 | 내용 |
|---|---|---|
| 우리 실험 | 7 | 3언어 AUC, 휴지 방향 역전, 버벅임 축 0.690→0.879, MCI 한계 0.598, 발화량 편향 통제 |
| 공개 벤치마크 | 2 | ADReSS/ADReSSo 양식별 정확도, 비편집 ASR 조건 |
| 임상 해석 | 7 | 휴지-단어찾기, 지시어 남용, 어휘다양성, 음질 교란요인, 발화속도, 순서회상, 진단 아님 |

각 근거는 ID와 원문을 가짐. 이 원문이 검증의 대조 기준이 됨

외부 논문보다 우리 실험 결과를 우선 배치함 — 재현 가능하고 인용 검증이 확실함

### 임상 7건은 참고문헌을 비워둠

내용은 확립된 임상 소견으로 작성했으나 `cite` 필드는 공란

* 논문 저자·연도를 지어내면 그것이 우리가 막으려는 환각 그 자체
* 제안서에 넣으려면 팀이 실제 참고문헌 확인 후 채워야 함
* 목록: `python3 -m src.rag.corpus`

## 검색

`src/rag/retriever.py`. 축 필터가 1차 게이트, 임베딩은 그 안에서 순위만 결정

* "발음 정확도" 점수에 "순서 회상" 근거가 붙는 사고를 구조적으로 차단
* Solar Embedding 사용, 실패 시 키워드 폴백(결정적이라 테스트에 유리)
* 축 이름과 코퍼스 용어가 달라 동의어 확장 필요했음
   * 축은 "침묵 시간", 근거는 "휴지" → 축명만으로 검색하면 못 찾음

## 해석

`src/agents/analysis/scoring/interpret.py`. 루브릭 + 검색된 근거 + 점수를 함께 줌

* 루브릭을 주면 모델이 점수를 다시 매기려 듦("62점인데 70점이 맞다")
   * 프롬프트에서 명시적으로 금지
   * 검증기가 점수 불변을 기계적으로 재확인 (프롬프팅이 1차, 규칙이 잔여분)
* 근거를 쓸 때 ID를 달게 함 → 검증 가능

## 검증 에이전트

`src/agents/analysis/scoring/verify_agent.py`. 채점자·해석자와 분리된 독립 판정자

### 검증자에게 자기 지식을 쓰지 못하게 함

"이 인용이 사실인가"를 모델 기억에 물으면 검증자도 환각함

* 대신 검색된 원문을 함께 주고 "이 주장이 이 원문에서 나오는가"만 물음
* 사실 확인이 아니라 원문 대조(entailment)
* 판정: supported / unsupported / overreach
* 원문에 없으면 사실이더라도 unsupported

### 검사 항목

규칙 검사를 먼저 돌려 확정적인 것을 걸러내고, LLM은 판단이 필요한 것만 봄

| 항목 | 주체 |
|---|---|
| 숫자 근거성 — 실제 점수·측정값·근거 원문에 있는 수치인가 | 규칙 |
| 점수 불변 — 해석 과정에서 점수가 바뀌지 않았는가 | 규칙 |
| 인용 유효성 — 허용된 근거 ID만 인용했는가 | 규칙 |
| 진단 단정 표현 | 규칙 + LLM |
| 원문 대조 — 각 주장이 인용한 원문에서 도출되는가 | EXAONE |

실패 시 지적사항을 피드백하며 재생성

### 더미 테스트 결과

* 허용되지 않은 인용: clin-made-up-source
