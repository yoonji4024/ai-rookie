# TTS 한계

## 왜 쟀나

데모 시나리오를 TTS 합성 음성으로 만드는데, 그 음성으로 음질 축을 검증할 수 있는지 확인
가설: TTS는 기계적으로 안정돼서 MCI 대본으로 만들어도 음질 지표가 정상으로 나올 것

## 방법

데모 wav를 실제 분석 파이프라인에 그대로 통과 (extract_acoustic → 발화 5축 스코어링)
실제 Kang 화자와 대조

## 결과

| | 총점 | 발음 정확도 | jitter | shimmer | CPP |
|---|---|---|---|---|---|
| TTS MCI형 | 92 | 100 | 0.0236 | 0.0920 | 13.08 |
| TTS 정상형 | 87 | 100 | 0.0259 | 0.1007 | 13.25 |
| 실제 HC_30 | 96 | 90 | 0.0266 | 0.1483 | 7.40 |
| 실제 MCI_63 | 24 | 6 | 0.0355 | 0.2030 | 4.64 |

* MCI 대본으로 만든 TTS가 발음 정확도 100점 — 실제 건강한 분(90)보다 높음
* CPP는 TTS 13.08 vs 실제 HC 7.40 → 합성이 실제 사람보다 1.8배 맑음
* 성대가 없어 jitter·shimmer 같은 불규칙성이 안 생김

## 대응

* 데모에서 음향 점수는 실제 Kang 화자 값 병행 표기
* 순서 회상·언어 축은 대본에서 나오므로 합성으로도 유효
* 합성 데이터는 분류기 학습에 미사용 (CLAUDE.md §7)

## TTS 설정

NC VARCO Voice — Text To Speech (Standard)

* 인증 `X-API-Key` (LLM은 Bearer, STT/TTS는 X-API-Key)
* 화자 목록 1293명 중 노년 65명 (여 18 / 남 47)
* 데모 기본 화자: 미리엘(중립) — 여성, 노년, 중음
* 감정 화자("분노", "슬픔") 피함 → 연기 톤이 음향 지표에 섞임
* speed 0.85 (MCI형) / 0.95 (정상형)
* seed 42 고정 → 같은 대본이면 항상 같은 음성
* text 1200바이트 제한 → 문장 경계로 나눠 합성 후 wav 이어붙임

## 대본 생성

Solar가 Kang 실측 차이를 근거로 회상 발화 대본 생성

* 실측 근거: 발화량 708초 vs 449초, 휴지 빈도, 대명사 과다 등
* MCI형에 누락 최소 1개 + 순서 혼동 최소 1쌍 강제
* omitted_scenes를 선언하게 해서 매칭기가 과다 매칭하는지 자동 검증
